# Property Empire — Android

Two Android shells exist side by side:

| Path | What it is | Status |
|---|---|---|
| `android/` | Hand-rolled WebView wrapper from v7 (AdMob interstitial + Play Billing bridge, `PropertyEmpireBridge`) | **Frozen reference.** Do not extend; it has no UMP consent, placeholder integrity keys, `targetSdk 34` and v7-era ad cadence. Kept only until the Capacitor app ships. |
| `android-capacitor/` | Capacitor Android platform generated by `npx cap add android` (P6.1) | **The store path.** Same web game, maintained shell. |

---

## Capacitor app (P6.1) — `android-capacitor/`

### How the web assets flow

The game has no build step, so the deployable web root is staged and Capacitor
copies it into the native project on every sync:

```
index.html, css/, js/ (minus js/sim), assets/, manifest.json
        │  stage (see list below)
        ▼
  capacitor-web/            ← capacitor.config.json "webDir"
        │  npx cap sync android
        ▼
  android-capacitor/app/src/main/assets/public/   ← packaged into the APK/AAB
```

To re-stage after changing the web game (from the repo root):

```bash
rm -rf capacitor-web && mkdir -p capacitor-web
cp index.html manifest.json capacitor-web/
cp -r css js assets capacitor-web/
rm -rf capacitor-web/js/sim        # test harness, never shipped
```

`capacitor-web/` is a generated artifact — regenerate it, never hand-edit it.
(Recommended: gitignore it and stage in CI before `cap sync`.)

### Setup, sync, verify

```bash
npm install                          # pulls @capacitor/cli, core, android, ios
npx cap ls android                   # parses capacitor.config.json
npx cap doctor android               # dependency + config health
npx cap sync android                 # stage capacitor-web first (see above)
```

Then open `android-capacitor/` in Android Studio and run/build as usual.
`npx cap add android` only needs re-running if the platform folder is deleted;
`cap sync` re-copies web assets and updates plugins.

### What replaces the hand-rolled wrapper

- The WebView shell, splash, back handling and permissions come from
  `@capacitor/android` (maintained) instead of the v7 `MainActivity.java`.
- `file://` asset loading is replaced by Capacitor's `https://localhost` asset
  loader with a working service-worker path.
- Monetisation plugins to add next (P6.2 follow-ups):
  `@capacitor-community/admob` (brings **UMP consent** with it — mandatory for
  EEA/UK) and a billing plugin (`@capacitor-community/play-billing` or
  RevenueCat). Until then `js/ads.js` runs its web fallbacks.
- The v7 `PropertyEmpireBridge` Java class is retired with the wrapper. The JS
  side (`js/ads.js`) talks to `window.PropertyEmpireBridge.*` when present and
  falls back to web behaviour otherwise, so the Capacitor plugin can reuse the
  same call surface (`showInterstitial`, `showRewarded`, `isAdsRemoved`,
  `purchaseRemoveAds`, `restorePurchase`, plus the `AdManager._onAdDismissed /
  _onRewardEarned / _onRewardClosed / _onAdsRemoved` JS callbacks).

### Anti-tamper: kept only where it is not theatre

The v7 `IntegrityChecker` ran signature checks **inside the APK it was
protecting**, with a placeholder key — pure theatre (audit
`docs/audit/03-engineering.md` §4). It is not carried over. What remains:

1. **Purchase state is native-authoritative.** The bridge's `isAdsRemoved()`
   (Play Billing / App Store receipt) decides; localStorage is only a cache.
   The v7 bug where the JS layer trusted `localStorage.pe_ads_removed` first
   and the web build granted removal via `confirm()` is gone
   (`requestRemoveAds()` explains instead of granting).
2. **Server-side verification** is the only real receipt check and can only
   exist once a backend does it (Play Developer API / App Store Server API at
   `PE.Analytics`' future flush endpoint or a dedicated verifier). Documented
   in `docs/monetization.md`; not faked locally.

### Signing / building

No builds were attempted in P6.1 (no SDKs in the dev container). On a machine
with Android Studio: open `android-capacitor/`, Build > Generate Signed
Bundle/APK. Keep keystores out of git. `targetSdk` comes from the Capacitor
template (8.x tracks current Play requirements — verify at release time).

### iOS status (Windows dev machine)

`npx cap add ios` generated the Xcode project at `ios/` on Windows (pure file
generation, no signing material needed), and `npx cap copy ios` staged the web
assets into `ios/App/App/public`. What cannot run on Windows is the rest of
the iOS toolchain: `cap update ios` needs CocoaPods (`pod install`) and any
build needs macOS + Xcode. Finish iOS setup on a Mac:

```bash
npx cap sync ios        # runs pod install
npx cap open ios        # Xcode: set team, then build/archive
```

## Legacy hand-rolled wrapper — `android/` (v7, frozen)

> Kept as reference only. The sections below describe the old APK build.

### Prerequisites

- [Android Studio](https://developer.android.com/studio) (Hedgehog or newer)
- JDK 17+
- Android SDK 34

### Build Steps

#### 1. Copy web assets into the Android project

```bash
cd android
./copy-web-assets.sh
```

This copies `index.html`, `css/`, `js/`, and `assets/` into `app/src/main/assets/web/`.

#### 2. Open in Android Studio

Open the `android/` folder as a project in Android Studio. Let Gradle sync.

#### 3. Generate app icon

Replace the placeholder icons in `app/src/main/res/mipmap-*/` with your own. Use Android Studio's **Image Asset** tool (right-click `res` > New > Image Asset) to generate all densities from a single source image.

#### 4. Build the APK

- **Debug APK**: Build > Build Bundle(s) / APK(s) > Build APK(s)
- **Release APK**: Build > Generate Signed Bundle / APK, then follow the signing wizard

The debug APK lands at `app/build/outputs/apk/debug/app-debug.apk`.

### What the app does

- Loads the full web game in a fullscreen WebView
- Enables `localStorage` for game saves (persists across app updates)
- Runs in immersive fullscreen mode (hides status/nav bars)
- Keeps screen awake while playing
- Locks to portrait orientation
- Back button is captured (no accidental exits)

### App icon

For now the mipmap folders are empty — Android Studio will use a default icon. To add your own:

1. Create a 1024x1024 PNG icon
2. In Android Studio: right-click `res` > New > Image Asset
3. Select your PNG and generate all densities

### Signing for release

To publish on the Play Store or sideload a release build:

```bash
# Generate a keystore (one-time)
keytool -genkey -v -keystore property-empire.keystore \
  -alias propertyempire -keyalg RSA -keysize 2048 -validity 10000

# Build signed APK via Android Studio's Generate Signed APK wizard
```

Keep `property-empire.keystore` safe and **never commit it to git**.
